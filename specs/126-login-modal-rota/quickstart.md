# Quickstart: Login em modal

Run from the repository root after implementation. Use only the seeded E2E account.

## Prerequisites

- Frontend and backend development dependencies installed.
- Backend E2E seed data and session cookie generated by the existing E2E seed workflow.
- Playwright Chromium installed for the frontend project.
- Do not use a production account, session cookie or password.

## Run validation

1. From `frontend`, run the production build with `npm run build`.
2. Run browser coverage with `npm run test:e2e`; the login scenarios should use the existing seeded auth fixture and must not expose credentials in screenshots/reports.
3. Review the Playwright/axe results; critical violations fail the existing quality contract.

## Browser scenarios

1. Open `/login` directly, submit valid credentials, and verify full-page login remains available. Refresh while on `/login` and confirm it is still full-page.
2. From Home, open each sign-in CTA. Verify the overlay opens without a document reload, the background remains visible, and valid login follows the CTA's safe internal destination.
3. Open login from UserMenu and verify login/cancel use SPA navigation and return to the same background screen.
4. Open `/painel` and `/painel/novo` while signed out. Verify modal presentation; cancel and confirm there is no reopen loop or protected content access; then log in and confirm the protected route resumes.
5. Use invalid credentials and simulate network failure. Verify modal/page presentation is retained, feedback is localized, and email remains available for retry.
6. Verify close button, Escape, backdrop behavior, Tab trapping and focus restoration by keyboard.
7. Log out and complete a password reset. Verify each leads to full-page login with no prior account/reset content behind it. Confirm Invite and Reset routes remain full-page.
8. Attempt a protocol-relative or external `next` destination; verify it cannot navigate outside the app.
9. Repeat key flows in pt-BR and en; run axe on modal and full-page states.

## Expected results

- Seven internal sign-in entry flows use one login modal without a full page reload.
- Direct `/login`, logout and reset-completion login are full-page experiences.
- Successful sign-in restores the source context or its explicit safe internal destination.
- Cancel from a public page returns to that page; cancel from a protected guard reaches a safe route without a loop.
- Failed login stays in place and exposes an accessible localized error.
- No auth password, session cookie or reset token appears in navigation state, URL or artifacts.
